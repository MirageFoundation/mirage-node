## Executive Summary

Full re-audit of the Mirage backend at the post-v1.32.2 remediation state. The cryptographic core (canonical envelopes, nonce guards, outer validator signing) and the Aug 5 Critical/High remediations **hold**: C-1 fee drain is closed, H-1 admin endpoints require signed identity, M-1 no longer trusts `X-Forwarded-For`, C-2's concurrent double-pay race is locked, and H-3's silent PoW-precheck skips are gone in favor of `_log_pow_precheck_error` plus a written trust model.

**What this cycle found that the remediations did not fully close** is concentrated in the reward payout path:

1. **C-2 is fixed; one of its remediation items was not implemented.** The reported vulnerability — unauthenticated claims and concurrent double-pay — is closed: `pg_advisory_xact_lock` (`reward_distributor.py:398`) is held across the payout *and* the `claimed_at` UPDATE through `commit` (`:581`), and post-grace claims require a signature. What was not done is the review's suggested *ordering* change (claim-before-pay). The residual is a crash window only: a worker killed between a successful `miraged tx` broadcast and `commit` rolls the rows back to unclaimed, so a later claim pays again. Not attacker-triggerable. See **L-1**.
2. **The unsigned-claim grace window was extended, not closed.** `LEGACY_UNSIGNED_UNTIL` moved from 2026-09-05 to **2026-10-05** in `d628eec6`, and failed proofs now fall through the same legacy path as missing proofs (intentional, for mobile builds). Until that cutoff, anyone can still force-claim any address's pending rewards to that address. Concurrent over-pay remains blocked. See **I-1**.
3. **Payout CLI parsing assumes success on non-JSON stdout** when return code is 0, which can mark rewards claimed without a verified `txhash`. See **L-2**.

**No finding in this cycle rates Medium or above.** The only attacker-reachable item is I-1, and that is a deliberate, dated product decision to keep older mobile builds working — not a regression or an unclosed vulnerability. No new privilege-escalation on admin routes, no return of XFF trust, no dummy outer signature, no new Critical. Upload remains unauthenticated by accepted risk (2026-08-05 M-4). The plaintext `test` keyring (2026-08-05 L-4) remains the largest accepted residual.

**Ship blockers:** None. **Nothing in this review warrants a dedicated release this month** — see [Urgency Assessment](#urgency-assessment--nothing-here-is-a-this-month-fix).

## Findings

### L-1: Reward Claim Pays Before Marking Claimed — Crash Window Can Double-Pay (Low — C-2 Remediation Item Not Implemented)

**Location:** `web/backend/reward_distributor.py` lines 478–581 (`claim_rewards`).

> **This is not a reopening of C-2.** The reported vulnerability is closed: the
> advisory lock at `:398` is held across the payout and the `claimed_at` UPDATE
> until `commit` at `:581`, so concurrent claimants cannot both pay, and
> post-grace claims require a signature. Only the review's suggested ordering
> change was skipped, leaving a non-attacker-triggerable crash window.

The Aug 5 C-2 remediation asked for claim-before-pay:

> `UPDATE pending_rewards SET claimed_at = %s WHERE … AND claimed_at IS NULL RETURNING …`. If it returns no rows, another request already claimed them. This inverts the current order so a crash can only ever under-pay…

What shipped is the advisory lock + signature (post-grace) + concurrent-claim test. The order is unchanged:

```478:503:web/backend/reward_distributor.py
                # Process MIRAGE rewards while the advisory lock is held so a
                # concurrent claim waits and then finds nothing unclaimed.
                if mirage_rewards and payout_amount > 0:
                    send_result = self.send_reward(
                        owner_lc, payout_amount, f"quest_rewards:{len(mirage_rewards)}_quests"
                    )
                    ...
                        # Failed to send - don't mark as claimed
                        ...
                        conn.rollback()
```

Marking happens only after a successful send (`:540–581`). `pg_advisory_xact_lock` serializes concurrent HTTP claimants for the lifetime of the transaction; it does not survive a process exit after the CLI has already broadcast. A worker kill, OOM, or deploy restart in that window leaves `claimed_at IS NULL` and the next claim pays again. Invite-code minting inside the same function uses separate autocommit connections, so minted codes can also survive a claim rollback.

**Impact:** Over-pay from the rewards pool under crash/restart timing only — an OOM kill, deploy restart, or host failure inside the window between broadcast and commit. No request an attacker can send produces it, and concurrency is already blocked. No crash-between-payout-and-mark regression test exists.

**Remediation:** Invert to `UPDATE … RETURNING` (or equivalent claim reservation) **before** `send_reward`; pay only for returned rows; treat “send failed after claim” as under-pay with an explicit recovery path. Add the crash simulation test the original review asked for.

### L-2: Payout CLI Treats Non-JSON Success Output as Success (Low)

**Location:** `web/backend/reward_distributor.py` lines 216–236.

After `returncode == 0`, JSON parse failure falls through to “assume success if no error code,” possibly with a heuristically scraped txhash or `None`. Combined with L-1, ambiguous CLI output can mark rewards claimed without a verified transfer, or confuse crash recovery.

**Remediation:** Fail closed unless `txhash` and `code == 0` are present in parsed JSON. Prefer Cosmos tx REST (`BROADCAST_MODE_SYNC`) over CLI for payouts, matching the backend's own write path. Stop hardcoding `--chain-id mirage-1` / `KEYRING_BACKEND = "test"`; take them from runtime config.

### L-3: `ROUTE_POLICY` Classifies Invite Routes as `DISABLED` With Empty Requirements (Low)

**Location:** `tests/cases/test_backend_authz.py` lines 104–112, 179–183; handler `routes/public.py` ~9865.

`/api/get_invite_codes` and `/api/validate_invite_code` are `DISABLED` → parity requires no `sig` markers. When `REGISTRATION_INVITE_CODE_REQUIRED` is on, the handler does call `_require_signed_read`, but removing that call would still pass `route_authz.policy`. Not exploitable while the flag is false (empty list / 404).

**Remediation:** When re-enabling invites, reclassify as `SIGNED_READ` (or a flag-aware policy) so the parity test pins the signed path.

---

### L-4: Soft Defaults Drift From Fail-Hard Policy (Low)

**Location:** `web/backend/settings.py` (`MEDIA_UPLOADS_ENABLED` defaults true if unset); `shared/config.py` soft defaults for keyring / `INDEXER_ENABLED`.

Peers use `require_bool_env` / fail-hard import patterns elsewhere (M-2 salt). Soft defaults are not a live exploit; they are the same class of opacity H-3 / M-6 tried to remove.

**Remediation:** Require explicit env for media uploads and indexer enablement in production templates.

### I-1: Unsigned / Bad-Proof Reward Claim Grace Extended to 2026-10-05 (Informational — Accepted Residual)

**Location:** `web/backend/settings.py` lines 105–116; `routes/quests.py` lines 809–833; migration `deploy/migrations/v1_32_3_extend_claim_grace_window.py`.

Until the cutoff, absent **or unverifiable** identity falls through and pays to the client-supplied `owner`. Payout still goes to that address (not an attacker wallet). Concurrent double-pay remains locked. `d628eec6` lengthened the window and deliberately equated failed proofs with no proof so legacy mobile builds are not 401'd. Tests now **require** that fallthrough during grace.

**Impact:** Anyone can trigger claims for any address with pending rewards until 2026-10-05 UTC. Funds do not divert to the attacker. Closes automatically at the cutoff unless extended again.

**Remediation:** Do not extend past 2026-10-05 without a recorded product decision. After cutoff, confirm unsigned and bad-proof claims return 401 in production.

## Positive Security Controls Observed (this cycle)

- **C-1 outer signing holds.** `tx.py` sets `fee.payer` to the validator and attaches a real secp256k1 SignDoc signature; placeholder bytes remain only in the size estimator.
- **H-1 / admin path holds.** Unsigned admin → 401, never 403-by-level on a spoofed address string.
- **M-1 IP trust holds.** No `X-Forwarded-For` reads in backend code; Caddy still injects `CF-Connecting-IP`.
- **Trust model is written down.** `docs/architecture/backend-trust-model.md` + core module docstring; PoW prechecks log failures instead of swallowing them.
- **Indexer fail-hard holds** and improved: dead indexer → 503 `indexer_unavailable`; trailing head treated as catching up (`d628eec6`) instead of opaque write 500s.
- **Route authz parity inventory is clean** at HEAD (0 undeclared / 0 stale / 0 policy violations) for the declared markers — with the invite `DISABLED` caveat in L-3.
- **Canonical encoding and push-nonce UNIQUE constraint** remain the right anti-reuse foundation.
