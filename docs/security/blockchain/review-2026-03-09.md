# Blockchain Security Review — 2026-03-09

**Scope:** `blockchain/` — all Go source (ante handlers, core module, bridge, orchestrator, proto/types, keeper), plus `go.mod`.
**Out of scope:** `web/`, `indexer/`, `deploy/`, external Solana programs.
**Baseline:** v1.18.0 security fixes from review-2026-03-08. HEAD: v1.18.0.

---

## Executive Summary

The v1.17.0 upgrade fixed all three previous critical findings and most high/medium issues. One critical vulnerability remains: relay envelope replay enables double-spend of token transfers. Biography length is not enforced on-chain and needs to be fixed. The bridge is not live — all bridge-specific findings are deprioritized.

**Ship blocker:** C-1 (relay envelope replay). Fix requires a coordinated chain upgrade.

## Findings

### C-1: Relay Envelope Replay — Double-Spend (Critical)

**Location:** `app/app.go` (relay ante chain), `app/ante_metasig.go` (`RelaySigDecorator`)

The relay ante chain bypasses the standard SDK `SigVerificationDecorator`. Replay protection relies only on timestamp freshness (~60 s) and block hash window (~10 blocks). No nonce or envelope-hash dedup exists. The outer SDK tx signature is never verified.

**Exploit:**
1. Alice signs an envelope to send 50 tokens to Bob.
2. Relay server broadcasts the wrapped SDK tx to the P2P network.
3. Attacker (any full node operator) extracts Alice's signed envelope from the mempool.
4. Attacker wraps the same envelope in a new SDK tx (different outer hash, attacker pays trivial gas).
5. Both txs pass ante checks — Alice's inner signature is valid, timestamp is fresh, block hash is recent.
6. Both txs execute: Alice loses 100 tokens instead of 50.

Same attack works on `MsgBridgeBurn`. For free-tier PoW users, the attacker extracts the `pow` nonce and replays it directly.

**Severity:** Any mempool observer can execute this against user funds. Private relay connections reduce but do not eliminate the window.

**Remediation:** Add a client-generated nonce to the signed canonical bytes. Store `hash(pubkey||nonce)` in an on-chain TTL set, rejecting duplicates within `max_envelope_age`. Requires coordinated chain upgrade.

### M-1: Biography Length Not Enforced On-Chain (Medium)

**Location:** `x/core/module/module.go` (`SetBiography`)

`SetBiography` validates safe text but enforces no maximum length. The frontend shows a 512-character limit, but the chain does not enforce it. A subscriber can store arbitrarily large biographies in the KV store.

Free-tier users (level 0) are correctly gated by `CanHaveBiography: false` in the tier config, but there is no character limit for tiers that do allow biographies.

**Remediation:** Enforce on-chain: **0 characters for free-tier (level 0), 512 characters max for subscribers and agents (levels 1, 10, 100+)**. Hard-cap in the handler. Should ship in the same upgrade as C-1.

---

### M-2: BlockPost Silently Swallows Gas Fee Error (Medium)

**Location:** `x/core/module/module.go` (`BlockPost`)

```go
_ = am.deductRelayGasFee(sdkCtx, owner, userLevel, gasUsed, "BlockPost")
```

Every other handler returns this error. BlockPost discards it. If profile persistence fails during the downgrade path inside `deductRelayGasFee`, the user is not rejected and enforcement is inconsistent.

**Remediation:** `if err := am.deductRelayGasFee(...); err != nil { return nil, err }`.

---

### I-1: Governance Can Set Invalid User Levels (Informational)

**Location:** `x/core/module/module.go` (`SetLevel`)

`core.Level = req.GetLevel()` accepts any int32. Levels 2–9 are undefined in `LevelToTierIndex` (returns -1), causing `GetTierConfig` to return nil. Requires compromised governance (honest-majority assumed).

**Remediation:** Validate against known levels (0, 1, 10, 100+).

---

### I-2: Orchestrator Error Detection via String Matching (Informational)

**Location:** `orchestrator/attestor/attestor.go` (`isPermanentError`)

Substring matching on `"TransactionTooOld"`, `"error: 6020"`, etc. Error message changes in Solana could silently drop burns or cause infinite retries.

---

### I-3: Non-Cryptographic PRNG for Retry Jitter (Informational)

**Location:** `orchestrator/chains/solana/watcher.go`

`rand.Intn` jitter is predictable. Could synchronize retry storms across validators under rate limiting.

## Not a Bug / Accepted Risk

| Item | Status | Rationale |
|------|--------|-----------|
| PoW difficulty float (`math.Pow`) | **By design** | All validators run identical amd64/Go. Cross-architecture divergence is theoretical — revisit if validator hardware diversifies. |
| Bridge float-to-BPS conversion | **Deprioritized** | Bridge is not live (`BridgeChains` config is empty, not deployed to production). Revisit when bridge launches. |
| Duplicate awards on same post | **By design** | Awards stack intentionally (e.g., 3x Quality Post). No dedup needed. |
| UpdateParams cannot set values to zero | **By design** | Partial-update `!= 0` logic is intentional. Acknowledged in v1.17.0 review. |
| PrepareProposal passes all txs | **Not a live concern** | Proposer tx stuffing wastes validator execution but is not exploitable for fund theft. CometBFT default behavior. Not deployed in a context where this matters. |
| Anon prefix on downgrade | **By design** | Username persists across tier changes. It is a user-chosen identity, not a trust signal. |
| SubscriptionPeriod = 0 | **By design** | Zero period means one-time payment with no renewal. Allows governance to configure non-recurring tiers. |

## Assumptions

- **Mempool visibility:** C-1 severity assumes P2P mempool is observable by any full node operator. Private relay reduces but does not eliminate the attack window.
- **Validator hardware:** All validators run identical amd64 hardware and Go version. PoW float arithmetic is accepted risk under this assumption.
- **Governance threat model:** I-1 requires compromised governance. Honest-majority assumed.
- **Solana program:** Out of scope. Mint replay protection and validator registry correctness are assumed.
- **Indexer trust:** Delete/Edit authorization is enforced by the indexer, not on-chain. The chain accepts these messages from anyone and the indexer gates ownership. A compromised indexer could subvert this.

## Test Coverage Gaps

- **Envelope replay across multiple txs in same block:** zero coverage — would demonstrate C-1
- **Biography length enforcement per tier:** zero coverage — would demonstrate M-1
- **BlockPost gas fee error propagation:** zero coverage — would demonstrate M-2
- **`processSubscriptions` full lifecycle:** renewal success, renewal insufficient balance, auto-renew disabled, one-time payment (period=0)
- **`deductRelayGasFee` downgrade path:** reserve exhaustion → level 0, profile persistence
- **`checkReserveOrDowngrade`:** paid user with zero reserve, admin bypass, free-tier passthrough
- **PoW difficulty adjustment:** busy window increase, calm sequence decrease, grace period acceptance
- **`MintIfNeeded` block reward distribution:** zero coverage
- **`DisableDelegatorStakingDecorator`:** self-delegation allowed, third-party delegation rejected
- **`EnsureAccountsDecorator`:** first-tx account creation for all whitelisted message types
- **Full relay vs standard ante routing:** governance messages forced to standard path, relay messages to relay path
- **Governance bypass (gov authority → standard path):** zero integration test coverage
- **Orchestrator `Run`, `replayPendingBurns`, `handleExternalBurns`:** zero coverage
- **Orchestrator signer (`submitWithGasRetry`, `buildUnorderedTx`, `waitForTx`):** zero coverage
- **Cross-architecture PoW determinism:** not testable in unit tests (requires multi-arch CI)
