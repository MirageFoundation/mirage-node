# Mirage v1.39.0 mobile migration guide

This guide matches the chain and backend contracts in v1.39.0. Do not invent fields.

## Routes and deep links

Replace `/t/:slug` with `/c/:slug`. Replace `/topics` with `/communities`. Keep `/t/:slug` and `/topics` as redirects. Remove agents, quests, referrals, and invite-and-earn screens.

Send `X-Mirage-Visitor` on every backend request. Keep a deferred campaign `ref` only until visitor attribution succeeds. Do not call a referral or signup-reward API.

## Posts

`MsgPost` field 101 is `community` (same tag as the old topic string). Field 106 is `protocol_version` and must be `1`. Comments leave community empty and inherit the parent. Root posts require a claimed community.

Backend `POST /api/core/post` requires `protocol_version=1` or returns `426 upgrade_required`. Prefer `community` in the JSON body.

Canonical signing for `MsgPost` appends uvarint `1` at tag 106 after the repeated media tags.

## Membership

`MsgJoinCommunity` payload is only `community` at tag 100. There is no target field. `MsgBlockCommunity` keeps `target=100` and `community=101`.

Joining stores `LIVE_DEFAULT` (mode 0). Pinning a team is `PINNED` (mode 1) plus `pinned_team_id`. Raw is mode 2 with no team. Pending operation key is `(message_type, community_or_empty, team_id_or_0, target_or_empty)`.

`GET /api/communities?joined_by={address}` lists joined communities. `/api/get_user_followed` is followed users only.

## Reads

Lens query param: `effective`, `default`, `team`, or `raw`. `team` requires `team_id`. `scope=current` is protocol 1; `scope=legacy` is protocol 0. Do not union them.

Filter order: node policy and personal blocks, then stored/raw/pinned/default lens, then team hidden post, team hidden author (follow bypasses only this), subscriber-only against `author_was_paid_at_creation`, then thread lock.

## Subscriptions

`MsgSubscribe` field 102 is `period_count` in `[1,12]`. Self-purchase, gift, and renewal share that field. Subscriber relays are zero-fee when the indexer projection says `effective_paid`. Daily quota is 250 finalized envelope messages per UTC day. Quota error is `subscriber_daily_limit_reached` with epoch, limit, used, remaining, and reset timestamp.

Do not send relay-reserve fields. Do not treat `level>=1` as paid. Use `effective_paid`.

## Creator claims

`POST /api/core/claim_creator_rewards` with strictly increasing `epoch_ids`, at most 30. `GET /api/creator/earnings?creator=` returns decimal-string amounts.

## Retired APIs (410)

`/api/get_topics`, `/api/search_topics`, `/api/core/follow_topic`, `/api/core/unfollow_topic`, `/api/core/block_topic`, `/api/core/unblock_topic`, agent and annotate routes, quest, achievement, invite, and referral-reward routes.

## Profile / bootstrap JSON

Expect `effective_paid`, `joined_communities`, `community_preferences`, `daily_quota` or null, `renewal_warning` or null. Do not expect `enabled_agents`, `followed_topics`, or relay-reserve fields.

## Cache invalidation

After join/leave/preference/team/claim settlement, invalidate community detail, community posts, teams, the affected thread, home, profile, search, inbox, and creator caches.
